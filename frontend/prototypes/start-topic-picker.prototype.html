Thermodynamics

Carnot cycle

Thermodynamics is the study of how energy moves as heat and work, and what that motion can and cannot do. It rests on four laws, from the zeroth (temperature is well defined) to the third (absolute zero is unreachable). Most course material builds from the first two.

The Carnot cycle is the idealised heat engine: two isothermal and two adiabatic steps between a hot and a cold reservoir. No engine between the same two reservoirs can beat its efficiency, which depends only on the two temperatures. It is the yardstick for every real engine.

The links are drawn here for honesty; today markdown links in a tutor turn are not session actions, so this variant is really plain text unless the renderer learns a link scheme. It also collides with the prompt rule that the first turn is "answer then END".

What feeds the card (decide after the surface)

(a) Prompt-only prose

  • Zero new code. Not clickable. Fights prompts.py: first turn must "answer then END", and prose must not duplicate a card.

(b) New tool: suggest_topics(mode, items[])

  • Same pattern as ask_check_questions: tool result persists on the message row, card survives reload, server owns the state.
  • Model decides broad vs specific and writes the items; the prompt has to say "call it in the first turn, still write the 2-4 sentence answer first" (never a tool-only turn).
  • Costs: openapi.yaml + gen_contracts, a tool handler, a stream event, a Vue card. Tap sends a learner message ("Let's start with Entropy") and optionally seeds subtopic_levels.

(c) Frontend-gated card, like showDiagnosticCard

  • Needs a one-shot endpoint (POST /api/sessions/{id}/suggestions or computed at create) that returns mode + items, then the card is a sibling of DiagnosticConsentCard gated on "no learner turn yet".
  • Nothing persists; dismiss is local. Cheapest for variant A/B; the only real option for variant C (there is no session yet).
